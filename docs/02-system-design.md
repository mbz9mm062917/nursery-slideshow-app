# システム設計

## 1. 全体アーキテクチャ

```mermaid
graph LR
  User[保育士 ブラウザ] -->|HTTPS| FE[Vue3 SPA<br/>Vite / Pinia / Vue Router]
  FE -->|REST API| BE[Spring Boot API]
  BE --> DB[(MySQL)]
  BE --> Storage[(ファイルストレージ<br/>写真 / 生成動画)]
  BE -->|@Async| Worker[動画生成ワーカー]
  Worker --> FFmpeg[FFmpegプロセス]
  FFmpeg --> Storage
  FE -->|進捗ポーリング| BE
```

## 2. アーキテクチャ方針と理由

### 2.1 フロントエンド: SPA + ウィザード形式

- Vue Router で工程ごとにルートを分ける
  (`/upload` → `/reorder` → `/title` → `/theme` → `/bgm` → `/duration` → `/preview` → `/generating` → `/download`)
- Pinia に「編集中のスライドショー」を1つのstoreとして持たせ、各画面はstoreの読み書きだけを行う
- **理由**: 画面 = 工程 = コンポーネントという1対1対応にすることで、保育士は「次に何をすればよいか」に迷わない。
  開発側も画面追加・削除がルーティングとstoreの変更だけで完結し、影響範囲が閉じる。

### 2.2 バックエンド: レイヤードアーキテクチャ

`Controller → Service → Repository` の3層構成とし、動画生成のみ `VideoGenerationService` として責務を独立させる。

- **理由**: MVPの機能規模では3層で十分にシンプルかつ十分にテスト可能。将来AI編集やテロップ機能を追加する場合も、
  Service層に新しいクラスを追加するだけで既存コードへの影響を抑えられる。

### 2.3 動画生成は非同期処理を前提とする

FFmpegでの動画生成は写真300枚規模だと数十秒〜数分かかりうるため、同期HTTPリクエストでは
タイムアウトやユーザーの待機体験悪化のリスクがある。そのため:

- 生成リクエストを受けたら即座に `job_id` を発行してレスポンスを返す（`video_jobs` テーブルで状態管理）
- フロントは `GET /api/video-jobs/{id}` を一定間隔でポーリングし、進捗バーに反映する
- サーバー側は Spring の `@Async` + `ThreadPoolTaskExecutor` で非同期実行する

  MVPの規模（保育園単位の利用）では外部メッセージキュー（Kafka/RabbitMQ等）は過剰なため採用しない。
  ただし `VideoJobQueue` インターフェースとして抽象化しておき、将来的な負荷増加時にキュー実装へ
  差し替え可能にしておく。

### 2.4 ファイルストレージ

- MVP: サーバーのローカルディスク（`uploads/`、`outputs/`）に保存
- `StorageService` インターフェースを定義し、実装をローカルディスク版とする。将来S3等のクラウドストレージへ
  差し替える場合も呼び出し側（Service層）のコードは変更不要にする。

### 2.5 拡張性のための設計ポイント

| 対象 | 設計 |
|---|---|
| テーマ追加 | `themes` テーブルにフレーム/アニメーション/背景/FFmpegフィルタ定義を保持し、レコード追加のみで新テーマを反映できるようにする |
| BGM追加 | `bgms` テーブルで音源ファイルパスと表示名を管理し、ファイル追加＋レコード登録のみで選択肢に反映される |
| テロップ・字幕（将来） | `slide_photos` テーブルにキャプション用カラムを後から追加できる正規化構造にしておく（今は使わない） |
| 認証（将来） | `projects` テーブルに `user_id` を今は持たせず、匿名UUID管理。将来カラム追加で認証と紐付け可能にする |

### 2.6 技術選定理由

| 技術 | 選定理由 |
|---|---|
| Vue 3 (Composition API) + TypeScript | 型安全性とロジックの再利用性（composables）を両立できる |
| Vite | 開発サーバー起動・HMRが高速で開発体験が良い |
| Pinia | Vuexより記述量が少なく、TypeScriptとの親和性が高い |
| Vue Router | ウィザード形式の画面遷移をURLとして表現でき、ブラウザバックにも自然に対応できる |
| Spring Boot | 実務での採用実績が豊富で、Web層・DI・非同期処理を標準機能で完結できる |
| Gradle | マルチモジュール化やタスクのカスタマイズが柔軟 |
| MySQL | テーマ/BGMのマスタ管理や進捗ジョブ管理などリレーショナルなデータと相性が良い |
| FFmpeg | 動画生成のデファクトスタンダードで、フィルタ機能によりテーマごとの演出をコマンドレベルで表現できる |
